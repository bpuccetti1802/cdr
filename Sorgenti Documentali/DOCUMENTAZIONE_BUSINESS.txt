1. OVERVIEW DEL SERVIZIO
================================================================================

Il modulo "be-firma-certificati-postazione" è un microservizio Java che gestisce
il ciclo di vita dei certificati digitali X.509 (PKCS12) associati alle
postazioni ANPR di Roma Capitale.

Scopo principale:
  - Archiviazione sicura dei certificati di firma digitale
  - Generazione di firme CMS/PKCS7 per documenti e identificativi
  - Verifica dell'integrità delle firme digitali
  - Erogazione delle credenziali criptografiche ai servizi interni

Ambito: Firma digitale di postazioni ANPR nel contesto del Sistema Informativo
di Roma Capitale.


2. STAKEHOLDER E UTENTI
================================================================================

CONSUMER PRINCIPALI:
  • mediation-ansc: mediatore principale che richiede certificati e firma dei

RESPONSABILI TECNICI:

3. FLUSSI DI BUSINESS PRINCIPALI
================================================================================

3.1 FLUSSO: Onboarding Certificato di Postazione
----------------------------------------------------

Trigger: Nuova postazione ANPR attivata in una sede di Roma Capitale

Attori: Amministratore di sistema, Postazione ANPR

Passi:
  1. Amministratore prepara il file PKCS12 del certificato e la password
  2. Richiama endpoint: POST /api/v1/certificati/upload
  3. Parametri inviati:
     - file: certificato in formato .p12 o .pfx
     - password: password di protezione del keystore
     - alias: identificativo univoco (es. 058091-PC-2611)
     - idPostazione: ID della postazione (es. 058091-PC-2611)
  4. Il servizio valida il file e la password
  5. Importa il certificato nel database Oracle
  6. Password criptata con algoritmo Triple DES (chiave configurata)
  7. Ritorna: id, alias, serialNumber, dati di conferma
  8. Certificato pronto per la firma

Output: Certificato archiviato e disponibile per la firma


3.2 FLUSSO: Firma Digitale di ID Postazione
---------------------------------------------

Trigger: Richiesta di firma proveniente da mediation-ansc

Attori: mediation-ansc, Servizio firma, Database

Passi:
  1. mediation-ansc richiama: POST /api/v1/certificati/{alias}/firma
  2. Servizio reperisce il certificato dal DB usando l'alias
  3. Decifra la password del keystore
  4. Carica il keystore PKCS12 in memoria
  5. Estrae la chiave privata e il certificato X.509
  6. Genera firma CMS/PKCS7 attached dell'ID postazione
  7. Persiste la firma generata in tabella REG_USER_ANPR_SIGN
  8. Ritorna: alias, idPostazione, serialNumber, firmaBase64 (in Base64)

Output: Firma CMS disponibile per la trasmissione ad ANPR

Frequenza: Ad ogni attivazione/rivalidazione di postazione


3.3 FLUSSO: Recupero Dati PKCS12 (Esportazione)
-------------------------------------------------

Trigger: mediation-ansc necessita della chiave privata per firma esterna

Attori: mediation-ansc, Servizio certificati

Passi:
  1. mediation-ansc richiama: GET /api/v1/certificati/{alias}/pkcs12
  2. Servizio reperisce il certificato dal DB
  3. Decifra la password
  4. Estrae i byte del PKCS12
  5. Encoda in Base64
  6. Ritorna:
     - pkcs12Base64: file PKCS12 encoded
     - password: password decifrata
     - aliasKeystore: alias della chiave nel keystore

Output: Credenziali criptografiche esportabili


3.4 FLUSSO: Verifica Firma Digitale
------------------------------------

Trigger: Validazione di una firma esistente (audit, compliance)

Attori: Applicazione client, Servizio verifica

Passi:
  1. Client invia: POST /api/v1/certificati/verifica
  2. Request contiene:
     - contenuto: documento originale (Base64)
     - firmaBase64: firma CMS da verificare (Base64)
     - certificatoBase64: certificato X.509 pubblico (Base64)
  3. Servizio verifica l'integrità della firma
  4. Verifica la corrispondenza tra documento e firma
  5. Valida il certificato X.509
  6. Ritorna: esito (true/false) + messaggio

Output: Esito della verifica firma


3.5 FLUSSO: Ricerca e Consultazione
------------------------------------

Trigger: Consultazione dello stato dei certificati

Attori: Amministratore, Sistema monitoring

Passi:
  1. Endpoint GET /api/v1/certificati
     → Lista tutti i certificati della sede corrente
     → Ritorna: id, alias, idPostazione, serialNumber, firmaIdPost, idSede

  2. Endpoint GET /api/v1/certificati/{alias}
     → Dettaglio di un singolo certificato
     → Ritorna: metadati completi

Output: Visibilità dello stato dei certificati


3.6 FLUSSO: Dismissione Certificato
------------------------------------

Trigger: Disattivazione postazione ANPR o revoca certificato

Attori: Amministratore di sistema

Passi:
  1. Amministratore richiama: DELETE /api/v1/certificati/{alias}
  2. Servizio cancella:
     - Record da REG_USER_ANPR (certificato)
     - Record da REG_USER_ANPR_SIGN (firma)
  3. Ritorna: conferma dell'eliminazione

Output: Certificato e firma rimossi dal sistema


4. ARCHITETTURA TECNICA
================================================================================

4.1 Stack Tecnologico
---------------------
  Framework:     Spring Boot 4.1.0
  Linguaggio:    Java 25
  JPA/ORM:       Hibernate con Spring Data JPA
  Database:      Oracle 12c+ (ANAG_USR schema)
  Crittografia:  Bouncy Castle 1.85 (PKCS7, PKCS12, X.509)
  API:           Spring Web MVC + OpenAPI 3.0 (Swagger)
  Build:         Maven 3.x
  Container:     Docker + Kubernetes

4.2 Connessioni e Dipendenze
-----------------------------
  Database Oracle:
    - Indirizzo: 10.173.9.85:1522
    - SID: DBSIPODV
    - Schema: ANAG_USR
    - Tabelle:
      • REG_USER_ANPR: archivio certificati PKCS12
      • REG_USER_ANPR_SIGN: archivio firme generate

  Microservizi interni:
    • mediation-ansc: client principale del servizio

  Configurazione centralizzata:
    • CORS_ALLOWED_ORIGINS: http://localhost:4202 (sviluppo)
    • TRIPLE_DES_KEY: chiave di cifratura password (env var)
    • DB_USERNAME, DB_PASSWORD: credenziali Oracle (env var)


4.3 Struttura del Codice
------------------------
  /config:          Configurazione Spring, OpenAPI, CryptoConfig
  /controller:      REST endpoints (CertificatoController)
  /service:         Logica di business (CertificatoService, FirmaService)
  /entity:          Mapping JPA verso Oracle
  /dto/request:     Modelli input (VerificaFirmaRequest)
  /dto/response:    Modelli output (ApiResponse, CertificatoResponse, etc.)
  /repository:      Query JPA verso DB
  /exception:       Eccezioni custom (CertificatoNotFoundException, FirmaException)
  /util:            Utility crittografiche (CryptoUtil, KeyStoreUtil)


5. DATI E TABELLE DATABASE
================================================================================

5.1 Tabella REG_USER_ANPR
------------------------
Schema: ANAG_USR
Uso: Archivio certificati PKCS12

Colonne principali:
  ID                  NUMBER - Chiave primaria (sequence)
  ALIAS_KEYSTORE      VARCHAR2(200) - Identificativo univoco del certificato
  ID_POSTAZIONE       VARCHAR2(200) - ID della postazione ANPR
  KEYSTORE_POSTAZIONE BLOB - File PKCS12 in binario
  PWD_KEYSTORE        VARCHAR2(200) - Password criptata (Triple DES)
  HOSTNAME            VARCHAR2(200) - Host della postazione
  ID_SEDE             VARCHAR2(20) - Codice sede Roma Capitale

Indici: ALIAS_KEYSTORE (UNIQUE)
Record tipici: 50-200 (una per postazione attiva)


5.2 Tabella REG_USER_ANPR_SIGN
------------------------------
Schema: ANAG_USR
Uso: Archivio firme digitali generate

Colonne principali:
  ID                  NUMBER - Chiave primaria
  ALIAS_KEYSTORE      VARCHAR2(200) - Riferimento al certificato
  ID_POSTAZIONE       VARCHAR2(200) - ID della postazione
  SN_KEYSTORE         VARCHAR2(200) - Serial number del certificato
  FIRMA_ID_POSTAZIONE VARCHAR2(4000) - Firma CMS/PKCS7 in Base64
  HOSTNAME            VARCHAR2(200) - Host della postazione
  ID_SEDE             VARCHAR2(20) - Codice sede

Indici: ALIAS_KEYSTORE (UNIQUE)
Record tipici: 1:1 con REG_USER_ANPR (una firma per certificato)

8. PERFORMANCE E LIMITI
================================================================================

8.1 Limiti di Sistema
---------------------
  Max Upload Certificato: 10 MB (spring.servlet.multipart.max-file-size)
  Max Request Size: 10 MB (spring.servlet.multipart.max-request-size)
  Timeout Connessioni: Standard Spring Boot (30s default)
  Thread Pool: Virtual threads abilitati (Java 21+)
  Fetch size DB: 50 record (Hibernate JDBC)

8.2 Throughput Atteso
---------------------
  Upload certificato: < 100 ms (I/O file + DB insert)
  Firma ID postazione: 50-200 ms (operazioni crittografiche)
  Verifica firma: 20-50 ms (validazione CMS)
  Query lista certificati: 10-30 ms (tipicamente < 100 record)

8.3 Fattori di Criticità
------------------------
  • Operazioni crittografiche CPU-bound (firma/verifica)
  • Timeout Oracle in caso di DB lento
  • Memory leak potenziale in gestione PKCS12 (attente release risorse)
  • Password in transito nel request body (sempre HTTPS in produzione)


9. SICUREZZA E COMPLIANCE
================================================================================

9.1 Misure di Sicurezza Implementate
-------------------------------------
  ✓ Cifratura password keystore con Triple DES
  ✓ HTTPS obbligatorio in produzione
  ✓ Validazione input (NotBlank, constraints)
  ✓ CORS configurato per domain specifici
  ✓ Keypair management con Bouncy Castle (crypto provider affidabile)
  ✓ No hardcoded secrets (tutti in env var / vault)
  ✓ SQL injection prevention (JPA parametrized queries)
  ✓ XSS prevention (REST API, no HTML templates)

9.2 Compliance
---------------
  • Firma digitale conforme a PKCS7/CMS (RFC 5652)
  • X.509 v3 certificates
  • Algoritmi: SHA256withRSA (standard per firma ANPR)
  • Archiviazione firme per audit trail
  • Tracciatura: database logs + Spring Boot actuator

11. OPERAZIONI COMUNI
================================================================================

11.1 Startup del Servizio
-------------------------
  Docker:
    docker build -t be-firma:1.0 .
    docker run -e DB_USERNAME=ANAG_USR -e DB_PASSWORD=... \
               -e TRIPLE_DES_KEY=... -p 8080:8080 be-firma:1.0

  Kubernetes:
    kubectl apply -k k8s/overlays/dev/
    kubectl port-forward svc/be-firma-certificati-postazione 8080:8080

11.2 Backup Certificati
-----------------------
  Backup database Oracle: standard backup DBSIPODV
  Backup PKCS12: inclusi in BLOB di REG_USER_ANPR
  Nota: La chiave Triple DES è richiesta per recuperare le password

11.3 Rotazione Certificati
---------------------------
  Processo:
    1. Preparare nuovo PKCS12 con certificato scaduto replacement
    2. Upload con nuovo alias (es. 058091-PC-2611-v2)
    3. Testare firma con nuovo certificato
    4. Aggiornare config mediation-ansc se necessario
    5. Disattivare vecchio alias con DELETE /api/v1/certificati/{old_alias}

11.4 Troubleshooting
--------------------
  Certificato non trovato:
    → Verificare alias con GET /api/v1/certificati
    → Verificare che certificato sia stato uploadato

  Firma fallisce:
    → Verificare TRIPLE_DES_KEY corretta (password non decifrata)
    → Verificare certificato valido (non scaduto)
    → Controllare disponibilità memoria JVM

  Connessione DB:
    → Verificare DB_USERNAME, DB_PASSWORD
    → Verificare raggiungibilità 10.173.9.85:1522
    → Verificare tablespace ANAG_USR disponibile
